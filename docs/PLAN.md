# Delivery plan

## Outcome

Freshly retrieve all accessible liked/bookmarked X sources, research each with
authentic evidence, independently review, and publish a private connected LLM wiki.
Continue processing future selections with the same contract. Keep public code
maintainable, tested, and independently reviewed.

## Sequential vertical slices

1. Fresh collection: authenticated pagination into empty private storage, restart
   support, immutable retrieval receipts, explicit coverage and error reporting.
2. Durable processing: import only the fresh collection; lease work, retain evidence,
   alternate backlog/new work, recover interrupted jobs, expose honest status.
3. Verified publication: typed research/evidence/audit schemas, authentic capture
   validation, independent review, reject unsupported/tampered claims, crash-safe
   publication with exact readback and a searchable source catalog.
4. Real research execution: bounded subscription-backed workers, source/thread/link/
   media recovery, separate verifier, durable budgets/retries, end-to-end live proof.
5. Connected LLM wiki: concept/entity synthesis with source provenance, useful
   navigation, contradiction handling, deterministic rendering and link audits.
6. Unattended operation: scheduling, locks, restart recovery, incremental collection,
   progress/health reporting, private deployment and full-cohort acceptance report.

Each slice receives a GitHub issue, isolated branch/PR, behavior tests, independent
review, remediation, and passing exact-head CI before merge and issue closure.

## Quality gates

- Python 3.11+; validated schemas and cohesive modules.
- Maintainability index >50 for each Python module, including tests/tooling.
- Lint/format, regression tests, security/privacy checks, deterministic fixtures.
- Integration tests for pagination, concurrent claims, expired leases, budgets,
  stale/tampered evidence, interrupted publication, source coverage, rendered links.
- Live qualification is distinct from synthetic test success.
- No private data in Git, GitHub issues/PRs, or CI logs; no paid API fallback.

## Completion evidence

The operational report must reconcile fresh collection coverage against published
and unresolved exact source IDs, verify every publication receipt and wiki link,
record remaining inaccessible sources with concrete recovery actions, and prove
that newly arriving selections enter a functioning scheduled process.

Do not call the project complete merely because code is merged, workers exit, or
the queue reports no unseen items. Do not weaken quality gates to meet a deadline.
